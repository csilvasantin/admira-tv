Endpoint operativo JSON-RPC: https://ainimation.studio/taza/mcp
GET muestra esta guía. POST atiende MCP. Sin redirección para el endpoint canónico.

Conectar

{"mcpServers":{"playertaza":{"url":"https://ainimation.studio/taza/mcp"}}}

Transporte HTTP; respuestas JSON o SSE según Accept. Ejecuta initialize, notifications/initialized y tools/list. No se necesita sesión MCP. El servidor acepta las versiones 2025-11-25, 2025-06-18, 2025-03-26 y 2024-11-05.

Herramientas principales

ToolUso
taza_project_readProyecto activo, revisión y disponibilidad del puente. Solo lectura.
taza_status_readÚltimo contenido publicado y GIF; no prueba reproducción física.
taza_status_writePublica name + verb o text. Rechaza orígenes ajenos al proyecto activo.
taza_nowEstado general. Los campos BLE/look heredados pueden ser históricos; no sustituyen al estado del puente ni la cámara.

tools/list es la lista autoritativa. Herramientas manuales de píxeles y animaciones están restringidas cuando hay una asociación activa.

Aviso de gestión de colas

Primero selecciona Starbucks · Gestión de colas en el player. El productor no debe cambiar automáticamente el proyecto para forzar su mensaje.

{
  "jsonrpc": "2.0",
  "id": 2,
  "method": "tools/call",
  "params": {
    "name": "taza_status_write",
    "arguments": {
      "project": "starbucks-queue",
      "via": "queue-follow",
      "name": "PEDIDO 42",
      "verb": "LISTO"
    }
  }
}

Con CanalKiosk activo este mismo aviso devuelve isError:true, sin sustituir el contenido. CanalKiosk usa via=adcelerate-best y source=mappedMusic; Yarigai usa via=yarig. La asociación por pantalla se gestiona desde el player.

API HTTP equivalente

Base: https://playertaza.csilvasantin.workers.dev

  • GET /api/store-binding: selección vigente.
  • GET /api/mug-status: estado publicado.
  • POST /api/mug-status: mismos argumentos que taza_status_write.
  • POST /api/store-binding: configuración deliberada desde el player; storeId y screen.

Límite: una escritura cada 3 segundos. Ante retry_ms espera ese tiempo. Si bubble.queued=false revisa el error; una cola aceptada tampoco confirma LEDs. No reintentes un envío físico confirmado. El puente vuelve a intentar contenido pendiente al recuperarse mientras la consola sincroniza.

Seguridad y segmentación

El endpoint actual no exige OAuth: la selección filtra funcionalmente los proyectos, pero project/via son etiquetas declaradas, no credenciales de identidad. No distribuyas el token Bubble ni la clave del puente. Los productores deben enviar por esta API; una llamada directa a Bubble no pasa por sus filtros.
